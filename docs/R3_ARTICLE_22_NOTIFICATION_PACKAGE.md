# Internal Article 22 Notification Package Checklist

**Purpose:** owner-input checklist for an operator notification under the current PMR personal-data review.
**Status:** NOT FILED / OWNER INPUT REQUIRED
**Not legal advice:** this document is not a filing, submission, registration, or compliance certificate.

## Current review basis

The narrow PMR review in `M13_PMR_PRIVACY_CHECK.md` checked the official publication register, the 2026 amendments, and the current consolidated Law No. 53-Z-IV text. Its factual conclusion remains that prior operator notification is required before real public Intake processing and that the exception analysis does not currently remove that requirement.

## Owner inputs required

- `OWNER INPUT REQUIRED`: operator's exact legal identity and status.
- `OWNER INPUT REQUIRED`: operator address and contact details for the notification.
- `OWNER INPUT REQUIRED`: exact lawful purpose(s) and processing start date.
- `OWNER INPUT REQUIRED`: categories of personal data and categories of subjects.
- `OWNER INPUT REQUIRED`: legal basis and processing operations.
- `OWNER INPUT REQUIRED`: technical and organisational security measures.
- `OWNER INPUT REQUIRED`: end condition/retention boundary and cessation procedure.
- `OWNER INPUT REQUIRED`: cross-border transfer facts, processors, and actual database/hosting location.
- `OWNER INPUT REQUIRED`: authorized body route, current form/schema, submission method, and evidence-retention location.

The route and current form were not located in the checked official material. Do not invent a URL, form number, address, filing fee, or acceptance outcome. Confirm them with the responsible operator or qualified local counsel before submission.

## Product facts to reconcile before filing

The package should be reconciled against the deployed privacy notice, D1/Workers configuration, Turnstile, Access, notification path, retention job, and actual production feature flags. Any change to those facts may require an update under the law and must be recorded rather than silently assumed.

## Evidence boundary

Retain only the official submitted material and confirmation/registration evidence in the owner-controlled location. Never place identity documents, bot credentials, private inquiries, clinical text, or raw personal-data exports in GitHub issues, this repository, public analytics, Telegram, or screenshots.
